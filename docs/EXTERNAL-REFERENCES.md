## 1. c1overzz/dsh-bili-scroll

**它做什么**：定时替你刷 B 站，按关键词搜视频，**读字幕原文再判断**，写日报；值得的会评论 @ 你。

**与看一阵相关的核心点**

- **文本优先**：先读字幕原文判断，**没有字幕的演示类视频才抽帧看画面**。截图判定只用在「文字说不清」的场景。
- 抽帧是"深读"的一步，粗筛完全不出图（省视觉 token）。
- **判重表**：同一个视频只处理一次，不重复花 token。
- **窄工具集**：跑那一轮只给它六个只读工具，路径写死，没有文件系统/联网。
- **提示词版本账本**（`charter.sha256`）：用户没改过就自动升级，改过就另存 `.new`，不覆盖。

**我们采纳了什么**

- ✅ 文本优先（看一阵默认不出图，文字不足 / 模型要求 / 高动态才出图）。
- ✅ 判重思路 → 我们做了**行级去重**（`freshLines()`）：只把新出现的 OCR 行喂给模型。
- ⚠️ 提示词版本账本：**建议采纳但还没做**（见 ROADMAP）。

**不照搬的地方**

- 它是"一次看完一条视频"，我们是"持续监控一个窗口"，采样与成本模型不同。

## 2. SAOS-3624/dsh-video-storyboard

**它做什么**：把视频切成带时间戳的编号分镜图（9–16 格），配字幕，一次给模型看。

**核心实现点（源码级）**

- **帧 = 镜头**：真切点切段，段内用"积分采样点"补段，一段一帧，时间轴永远连续。
- **格子大小 = 该位置的切点密度**（8 档，边长 1/k）：快切处小格、长镜头大格。
- **切点算法**：缩到 64×36，逐帧比 HSV（色相环形距离、按饱和度降权）→ 自适应阈值 → 2 秒窗口爆点重判。
- **排版**：按行 DP 打包到方形画布，装不下开新图，排完**裁到内容**；填充率 <68% 时把长段再切几刀补帧。
- **auto 档**：张数只按时长算（默认 240s/张），预算内挑最省档；`dryRun` 先问成本。
- **像素计费**：42px 一格，`rows×(cols+1)+2`；单图 token 与格子数无关，与像素有关。

**我们采纳了什么**

- ✅ 拼图**按信息量分配**行高与列宽（简版"密度分配"，未做逐格 1/k 与 DP 打包）。
- ✅ 用局部块差找变化点（判变三路信号之一）。
- ✅ 像素计费概念（我们用 1.5k/张估算）。

**没采纳 / 为什么**

- ❌ 按镜头切段：我们输入是**屏幕像素流**（2 秒一帧），拍不到 0.3 秒快切，且用户明确不信 OCR/多模态判镜头。
- ❌ 完整 DP 打包：当前收益不值得复杂度，先做行高+列宽。

## 3. SAOS-3624/dsh-watch-together

**它做什么**：陪看视频——跟着真实播放位置，每段结束前把分镜 + 台词递过去；悬浮窗能出声、能听房间。

**核心实现点**

- **变速启动** `ramp: [60,120,180,240]`：开头短、逐段加长，第一次说话不用等 5 分钟。
- **双缓冲**：永远留一个批次在后面，交付实测 0.0 秒。
- **lead 15 秒**：段末前交付，不在边界插话。
- **进度读数**：浏览器扩展上报 `currentTime`（或调试端口），读数新鲜/外推/错过一次/连续错过四档处理，宁晚不早。

**我们采纳了什么**

- ✅ 变速窗口（10/15/30 秒）。
- ✅ 双缓冲思路 → OCR 预取（并发 2），停止耗时从 ~10s 降到 1–2s。

**没采纳 / 为什么**

- ❌ 读播放进度：需要浏览器扩展；我们是窗口像素流，没有 `currentTime`。
- ❌ lead 交付：录制没有"播放进度"可提前，改为"段结束即算"。

## 4. Alterssss/dsh-bili-whale

**它做什么**：会按作息刷 B 站、写日记、评论的"鱼"。

**与看一阵相关的核心点**

- **六路互补**：官方字幕 + 弹幕热区 + 热评 + 抽帧看画面 + 封面 + 简介，缺一路不影响其它路。
- **九宫格固定 9 帧**：整条视频按 `duration/9` 等间隔取帧（90 秒 → 10 秒/帧；25 分钟 → 167 秒/帧）。
- **镜头切点优先**：ffmpeg `select='gt(scene,th)'` 空跑拿 `pts_time`，切点够 9 个就从切点挑，不够退回等间隔。
- **`--substrip`**：把画面底部 17% 字幕带按 **每 7 秒一帧** 竖拼成一张长图，整片台词一张图读完。
- 它确实**下载视频文件**再跑 ffmpeg（在线视频 → 本地文件），不是"在线流处理"。

**我们采纳了什么**

- ✅ "多路互补"的思想：文字 + 变化点 + 画面三条证据。
- ⚠️ `substrip`（字幕带裁条）暂不需要：我们 OCR 直接产出文字。

**没采纳 / 为什么**

- ❌ 固定 9 帧整片：我们是持续录制，每段都要反馈。

## 5. Sacredbluedragon/dsh-bili-watch

**它做什么**：链接 → 结构化视频内容（元数据、评论、弹幕、字幕、ASR、抽帧 OCR）。

**核心实现点**

- **三级降级链**：官方字幕 → 本地转写 → 画面认字；**哪级没成都会写进"来源"行**，不把截图文字当台词。
- **画面索引格式**：`r1c1 00:00-00:05 @00:02`（行列 · 覆盖时段 · 实际取帧时刻）。
- **缓存策略**：默认保留 7 天 / 上限 2GB；清理只删能证明归属的条目。

**我们采纳了什么**

- ✅ 索引格式（拼图格子与时间线共用 `r1c1` 式编号）。
- ✅ 缓存/保留策略（看一阵拼图 7 天清扫 `sweepSheets()`）。
- ✅ "失败要写来源"：我们的空档段、`needsVisual` 都是显式标注，不假装看过。

## 6. ilps2/dsh-video-understand

**它做什么**：把视频压成"信息层"（ASR + 场景 + 运动轨迹 + YOLO，约 1k token）再喂 LLM。

**核心实现点**

- 信息层替代逐帧像素；同视频内容哈希缓存复用。
- 分级：L0 信息层（本地）/ L1 少量 VLM 帧 / L2 时间窗密集帧。

**我们采纳了什么**

- ✅ "信息层"思想：OCR 文本层 + 时间线就是我们的信息层。
- ⚠️ 内容哈希缓存：部分采纳（行级去重），未做跨会话缓存。

## 横向对照：段/帧/成本

| 维度 | 它们（视频文件） | 我们（窗口像素流） |
|---|---|---|
| 时间分辨率 | 24–30 fps（可逐帧扫） | 1–20 秒一帧（受采样配置） |
| 场景切分 | ffmpeg scene / 镜头检测 | 像素差 + 时间分桶（不做镜头识别） |
| 音频 | 多数下载后 ASR/字幕 | **无**（见 AUDIO-DESIGN） |
| 单位 | 一条视频 | 一次录制（可 50 分钟） |
| 帧预算 | 整条 9 帧 | **每段 9 张图 / 12 帧文字** |
| 交互 | 一次问答 | 每 10–90 秒一次反馈 |

## 13. EXarchive/dsh-screen-attention

**它做什么**：Windows 10/11 上的 DSH 插件。Node 侧 59 个工具 + C# .NET 9 原生 helper（SaHelper，3356 行），
本地 ONNX 推理：PaddleOCR PP-OCRv4、YOLOv8n/m、Chinese-CLIP ViT-L/14（1.16GB）、YOLOv8n-face；
能力覆盖持续观察、数字人/ACG 角色识别、鼠标键盘自动化、权限分级与急停。

**三条频率铁律（它写在蓝图第 0 节）**

1. 60fps 是采集能力上限，不是运行目标——频率由 AI 按需控制；
2. **采集与识别解耦**：采集固定高频只做帧缓冲 + 变化检测，识别按预算消费；
3. 识别全文不进对话，只注入变化摘要（≤500 token/step），图片按需索取。

**与我们高度相关、值得抄的机制**

| 机制 | 它的数字 | 对我们的意义 |
|---|---|---|
| **FrameHub 单流 + 引用计数** | 100ms 一帧；无人订阅自动停止 | 「不要前端一套、后端一套采集」——我们也是单循环，但值得把"引用计数归零即停"作为约束写死 |
| **静止降频 + 心跳** | 每 10 帧（~1s）一次心跳；CPU 80% → <10% | 与我们的锚点帧同思路，但它是"降推理不降采集"；我们可以学"心跳帧只做判变不做 OCR" |
| **变化区域 OCR** | 只 OCR 变化包围盒 +12px padding；全屏 474ms → 并行分条 68.6ms | 我们目前整帧 OCR。长视频/大屏上，只 OCR 变化框能省一大截 |
| **框级 OCR 缓存（FNV 签名）** | OCR 300ms → 70–110ms | 静态浮层（标题/播放量）不重复识别；比我们的"行级去重"更靠前一层 |
| **变化三分类** | `content_change` / `dynamic_noise` / `text_shift` / `idle` | 我们只判"变没变"；"变了但文本没变"（视频/动画）可以直接不调模型 |
| **按变化量选帧** | HSV 64×36 网格打分；切点分 ≥12 且 >2.5×邻居且 ≥0.4s；积分 4 分×fps×3 秒 | 我们的"加权时间分桶"是它的简化版；它的阈值是真实标定的，可参考但受我们 2s 采样限制 |
| **多帧拼图省 token** | 4 帧拼一张 = 591 token（每帧 148），比看 4 次省 75% | 给我们拼图成本一个外部校准点 |
| **vision 单图 token** | 1260 宽、42px 对齐 ≈ 530–590 token/张 | 与我们 2160×1350（≈1660 token）的估算吻合，验证了 1.5k/张 的量级 |
| **锁窗口客户区** | 同一段视频：全屏变化分 6，只抓窗口 81（差 13 倍） | 我们已按窗口 id 截（`-o` 去阴影），但没裁标题栏；噪音可再降 |
| **隐私黑名单涂黑** | 1Password / KeePass 窗口矩形自动涂黑 | **我们缺这条**。持续录屏时这比什么都重要 |
| **看门狗自愈** | helper 崩溃 800ms 内重启并恢复观察模式 | 我们有退避重启；没有"恢复状态"与持久审计日志 |
| **急停** | Pause/Break 热键 100ms 锁死所有输入注入 | 我们不做输入注入，风险面小；但"一键停止录制"值得补 |

**不建议照搬**

- 本地模型栈（PaddleOCR/YOLO/CLIP/face，模型 3.95GB、helper 内存 2.5GB）：Windows + 本地算力路线，我们是 macOS + 云端模型，成本结构不同。
- 59 个工具 / 11 个角色管理工具：面向"ACG 角色识别 + 自动化"的产品目标，与看一阵无关。
- 鼠标键盘注入与分级审批：我们不注入，不引入这套权限面。

**可执行的采纳顺序（给我们的 backlog）**

1. **隐私黑名单**（窗口标题/应用匹配 → 不截、不 OCR、不落盘）——持续录屏的风险最大，成本最低；
2. **变化区域 OCR**（只识别变化包围盒，静态区域跳过）——OCR 时间与成本都能降；
3. **框级 OCR 缓存**（FNV 签名）——静态浮层不重复识别；
4. **变化三分类**——"动态噪声"（画面变了但文字没变）直接跳过模型调用；
5. 锁窗口客户区（裁掉标题栏）——进一步降噪。

**它自己也踩过的坑（值得记）**

- "前端一套、后端一套采集"被用户否掉，最终统一到 FrameHub 单流；
- 温度：stdio 必须 UTF-8、图片交付走文件路径而不是进上下文、视觉后端 429 要能回退；
- 静止降频必须留心跳，否则"画面刚恢复变化"要等很久才被重新识别。
